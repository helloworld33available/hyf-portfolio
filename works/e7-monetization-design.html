《第七史诗》商业化系统策划案 · 回声铭牌 EM

针对《第七史诗》长尾付费塌陷，提出「回声铭牌 EM」记账型反馈模块：以重复获取角色的残余价值为锚点重新计价，用资源类与典藏类双目录把回收出口与版本通胀预算隔开，并对肝帝、氪佬、又氪又肝三类人群分别做发行预算校验。含完整配置表结构与核心逻辑伪代码。

目录

    新增模块：回声铭牌 —— 重复产出代币化与定向兑换系统

    一．提案摘要

    1.1 核心结论

    本模块要把重复获取的角色从"零价值产物"改造为"可回收进度"，从而在不提高出货率、不降低价格、不售卖战力上限的前提下，重建长线付费的价值出口。

    一句话版本：玩家每次抽到已经拥有的角色，把它折算成统一代币，代币可以在严格受限的清单里兑换东西。它解决的是"抽卡边际价值衰减"这个结构性问题，而不是"出货率不够"。

    结论 说明
    问题定位 角色库完备后，单次抽取的价值期望衰减至初始值的约一成，付费意愿随之塌方
    手段 在既有传承体系之外，补一条可对齐当期目标的回收通道，而不是替换它
    边界 不售卖 5★ 本体，不接触金币与体力，不参与保底计数
    期望收益 处于稳定期的中重度玩家的付费深度回升，而非新增一次性收入

    1.2 标注体系

    标注 含义
    【实测】 来自既有实装或官方公告的确定信息
    【假设】 本提案给出的拟定参数，需在开发中调参与校准
    【待确认】 依赖客户端实现或既有配置的细节，需在评审时确认

    1.3 设计约束清单

    任何方案细节若与下列约束冲突，一律以本清单为准。

    编号 约束 原因
    C1 不得提高属性天花板 现行体系的天花板固定，破坏后永久改变战力环境
    C2 不得改变日产出与战力脱钩的关系 该关系是长线经济稳定的基础
    C3 不得以任何形式放开金币或体力的付费购买 金币闸门是双汇率结构的前提
    C4 代币不得计入保底计数，也不得兑换保底 保底锚点是留存设计的一部分
    C5 本模块带来的额外资源投放，占月总产出比例不得超过 5% 通胀红线
    C6 每件兑换物都必须满足"不改变既有玩家行为目标" 避免新增入口反而扰乱循环
    C7 典藏类兑换物不得携带任何数值，也不得折算为资源 使其可以不占月度预算而不引发通胀

    二．背景与问题定义

    2.1 现行结构的三处短板

    同系列《商业化系统拆解案》第六章给出三处短板，本模块针对其中前两处。

    短板 量化表述 本模块是否覆盖
    抽卡边际价值衰减 ρ 现状约 0.05，r = 0.9 时 V ≈ 0.15 V0 覆盖，为本模块主要目标
    终局阶段缺少付费出口 收敛所需资源大多不进商店 部分覆盖，兑换清单包含部分终局材料
    断层期缺少承接产品 第二至第三个月存在转化窗口 不覆盖，需另一独立方案

    2.2 既有回收机制与它的缺口

    重复获取的角色并非完全没有出口。玩家可以把多余英雄通过传承转化为传承石，再在传承石商店兑换。因此本模块不是从无到有创造回收，而是补上现有出口没有覆盖的那一半。

    既有机制 作用 可兑换范围
    记忆烙印 重复英雄提升该英雄与队伍的属性【攻略】 不适用
    传承 多余英雄转化为银光或金光传承石【攻略】 传承石商店
    传承石商店 周限购，金光兑换银河书签，萝卜约 15 银光/个【攻略】 种类固定，不随版本目标变化

    现有出口的三处缺口：

    缺口 说明 后果
    兑换目标与当期目标错配 传承石主要指向月光召唤与固定商品，而玩家当期最需要的往往是 UP 进度与终局材料 回收来的价值用不到当前需求上
    出口狭窄且一口价 商品种类固定，不随版本轮换【待确认轮换规则】 回收价值不随"抽到什么"变化
    缺少累积感 传承是一次性动作，没有进度条 无法提供"再抽几次就有回报"的牵引

    因此现状的 ρ 不是零，它由记忆烙印与传承石共同构成，量级估计在 0.05 上下【假设】。上一节的衰减结论依然成立，原因不在于没有回收，而在于回收来的东西不是玩家当时想要的东西。

    2.3 问题的定量表述

    设通道可获取对象集合大小为 N，玩家已拥有且无需再次获取的对象数为 n，重复率 r = n / N， ρ 为重复产出的回收率，则单次获取的价值期望为：

    V(n) = V0 × [ (1 - r) + ρ × r ]
    拥有率 r ρ = 0.05（现状） ρ = 0.10 ρ = 0.15（目标区间上限）
    0.50 0.53 V0 0.55 V0 0.58 V0
    0.70 0.34 V0 0.37 V0 0.41 V0
    0.90 0.15 V0 0.19 V0 0.24 V0
    0.95 0.10 V0 0.15 V0 0.19 V0

    处于结构末端的玩家（r = 0.95）在现状下单抽仅剩 0.10 V0。即使把 ρ 提到 0.15，也只能回到 0.19 V0。单纯提高回收比例的边际效益有限，这一点决定了本模块不能只靠"多发代币"取胜。

    因此本模块同时引入第二条作用路径：

    路径 机制 作用
    价值路径 重复产出折算为代币 直接抬升 V(n)，量化可测
    目标路径 代币只能兑换一份严格受限、且带进度条的清单 为"抽到的东西没用"提供可见的补偿进度，转变抽卡失败的情绪走向

    目标路径的价值不计入 ρ，但它对长期付费留存的贡献不低于价值路径。

    2.4 目标用户：肝度与氪度二维分层

    本作作为主游，玩家的投入由两条不能互相替代的通道构成：时间投入（肝度）与金钱投入（氪度）。日常产出受体力量约束，付费只能压缩等待时间。因此人群必须按二维划分，不能只按付费额排队。

    人群 肝度 氪度 月抽取量（估） 5★ 重复率 r5 现状痛点
    肝帝 高，日常与周常全清 低，多为月卡 70 至 120 抽【攻略】 0.50 至 0.60【假设】 单位时间收益有硬顶，进度上限由体力决定
    氪佬 低，不刷商店、不打满日常 高 300 至 500 抽【假设】 0.85 至 0.90【假设】 钱买不到金币与终局材料，付费效率受时间闸门压制
    又氪又肝 高 高 500 至 700 抽【假设】 0.90 至 0.95【假设】 进度最快，也最早撞上边际价值衰减

    一条容易被忽略的结构特征：只氪不肝的玩家在本作中效率偏低。双汇率路径需要反复刷新秘密商店并消耗金币，而金币产出由体力决定。付费能买到抽取次数，买不到把次数转化为效率的那部分时间。这解释了为什么该作的重度用户大多集中在又氪又肝这一格。

    设计目标按优先级排列：提升稳定期用户的付费深度 > 拉动一次性收入；维持现有留存曲线不劣化 > 短期流水增长。三类人群都必须获得正向感知，且任一人群的相对位置不得因本模块而变动。

    2.5 三类人群的 EM 收支测算

    沿用 5.2 的公式，取 G5 = 180 EM、G4 = 4 EM，对三类人群分别测算。

    人群 T（月抽取） r5 月获取 EM（估） 折合抽等价 名义投放占比 受上限后实际投放占比
    肝帝 120 抽 0.60 约 196 EM 4.9 抽 4.1% 4.1%
    氪佬 400 抽 0.90 约 954 EM 23.9 抽 6.0% 1.3%
    又氪又肝 600 抽 0.95 约 1510 EM 37.8 抽 6.3% 0.8%

    名义占比指的是按获取量计算的资源投放，氪佬与又氪又肝两组均已越过 5% 的红线。但引入月度兑换上限之后，实际投放被压到 1.3% 与 0.8%，红线得以守住。也就是说，兑换上限同时承担两个职能：通胀闸门，以及对重度玩家投入产出的硬约束。

    这张表同时暴露出一个必须解决的问题：若上限统一设为 200 EM，氪佬只能花掉其获取量的约两成，其余既不能花也不能继续积攒，因为余额上限 400 EM 会继续截断。这会直接制造"赚得多却花不掉"的负面体验，而这部分用户恰恰是本模块最想留住的人。

    处理办法是把兑换物分成两类，只对其中一类施加月度预算。

    类别 内容 是否计入 C5 预算 月限
    资源类 书签、强化石、进化材料、转换根源、神秘书签 计入 累计 200 EM
    典藏类 外观代币、展示类道具、收藏进度 不计入，因其不进入数值经济 无月限

    这样安排的结果是，重度玩家溢出的 EM 有出口，且出口落在不产生数值的典藏类上。既守住了通胀红线，也没有把肝帝挡在门外。

    2.6 明确不做的事

    项 若做会怎样 不做的原因
    代币兑换 5★ 英雄本体 等于把概率商品改为直购 摧毁保底与稀缺性设计
    代币兑换金币 打开双汇率的第二条收费口 违反约束 C3
    代币兑换体力 与体力闸门冲突 违反约束 C3
    引入独立付费货币 增加货币层级与玩家理解成本 违反简洁原则
    随版本递增兑换数量 后期无法收敛 违反约束 C5

    三．候选方案对比与取舍

    候选 核心机制 优点 致命问题 结论
    A 提高保底强度 硬保底由 121 抽下调至 90 抽 实现简单，短期数据提升明显 永久改变保底锚点且不可回滚；对角色库已完备的玩家毫无改善 否决
    B 新增高品质皮肤线 付费直购外观 不触碰数值，口碑负担小 美术产能投入大；拉动的是新需求，解决不了存量问题 不作为主方案
    C 重复产出代币化 重复获取折算为代币，受限兑换 直接命中边际价值衰减；不改动概率、保底、价格与天花板 需要严格控制兑换清单与总量 采纳

    方案 C 的成立前提是它不改动任何既有参数：概率不变、保底不变、价格不变、属性天花板不变。变化只发生在"抽到之后怎么处理"这一步，因此风险可控且可回滚。

    四．模块机制设计

    4.1 核心循环

    步骤 触发 系统动作 约束
    1 召唤结算完成 判定本次获取是否为重复获取 首次获取不发放代币
    2 确认为重复获取 按稀有度与来源发放对应数量的回声铭牌 神器维度不发放，沿用既有回收机制
    3 余额达到或超过 400 EM 停止累计，超出部分不记账 余额上限抑制囤积
    4 玩家发起兑换 校验清单、余额与月度额度后扣除并发放 三项校验全部通过才执行
    5 大版本结束 余额清零 防止跨版本囤积集中释放

    4.2 代币发放规则

    代币命名为回声铭牌，记为 EM。计量单位锚点取"一抽"：

    1 抽 = 5 枚圣约书签 = 40 EM
    来源 发放量 判定条件 备注
    重复获取 5★ 三色英雄 180 EM【假设】 该英雄已在玩家图鉴中 主要发放来源
    重复获取 5★ 月光英雄 540 EM【假设】 同上 月光获取成本显著更高，按比例上调
    重复获取 4★ 英雄 4 EM【假设】 同上 发放量极小，仅维持感知
    重复获取 3★ 与 3★ 以下 不发放 不适用 避免发放量失控
    重复获取神器 不发放 不适用 已有 Powder 类回收机制，不设双份

    发放入口统一走召唤结算之外的独立服务。这样做的原因是发放逻辑与抽卡结算解耦，后面无论新增卡池类型还是调整发放量，都不需要改动抽卡主流程。

    4.3 兑换清单

    清单分为资源类与典藏类，区分标准是该物品是否进入数值经济。

    资源类（累计兑换上限 200 EM / 月，计入约束 C5）：

    兑换物 单价 EM 月限次数 折合抽等价
    圣约书签 ×5 40 3 1.0 抽
    记忆烙印材料（当期 UP 指定） 80 2 2.0 抽
    万能强化石 90 2 2.25 抽
    指定套装进化材料 ×3 100 2 2.5 抽
    转换根源 120 1 3.0 抽
    神秘书签 ×50 200 1 不作抽等价折算，限重度玩家

    典藏类（不计入 C5，无月度预算，仍受余额上限约束）：

    兑换物 单价 EM 月限次数 说明
    回声典藏外观代币 300 不限 重度玩家溢出 EM 的主要出口
    展示类道具（头像框、称号） 150 不限 肝帝与氪佬可获得同等机会
    收藏进度解锁 200 起 不限 纯展示，与图鉴联动

    典藏类之所以可以不设月限，依据是约束 C7：它们不携带任何数值，也不得折算为资源，因此不影响 faucet 与 sink 的平衡。

    不可兑换部分及原因：

    项目 不可兑换原因
    5★ 英雄本体、月光 5★、限定角色 一旦开放，概率商品变为直购，违反约束 C1 与 C4
    金币 会撕开双汇率结构，违反约束 C3
    体力与叶子 与体力闸门冲突，违反约束 C3
    保底计数 保底是留存锚点，不可交易
    天空石 会造成代币与付费货币的直接兑换，破坏货币层级

    清单设计遵循一条简单判定规则：只要某物品能直接改变战力或能替代付费动作，就不进入清单。

    4.4 边界与限制规则

    规则 取值 目的
    发放对象 仅限英雄维度 避免与既有回收机制重叠
    余额上限 400 EM 抑制囤积，制造兑换决策
    月度兑换上限 资源类 200 EM；典藏类不设月限 落实约束 C5，同时避免重度玩家赚得多花不掉
    清零周期 大版本结束时 防止跨版本集中释放
    跨服继承 同一账号共用 实现上按同一分区处理
    回归玩家 不清零至上限内的部分【待确认】 避免回归即清零的负面体验
    类别判定 新增兑换物须先判定是否进入数值经济 防止典藏类混入数值道具

    4.5 异常用例清单

    场景 处理
    兑换时同时触发余额不足与月度额度不足 按余额不足提示，不消耗额度
    同一请求重复提交 以请求号做幂等，不重复发放
    版本切换瞬间发起兑换 以版本切换完成时点为界，之后的余额按新周期计
    兑换物已达月限 置灰并显示重置时间
    玩家同时兑换多项 逐项独立校验，互不影响

    五．数值模型

    5.1 参数与锚点

    参数 取值 来源
    p5，单次获取 5★ 英雄的概率 1.25%【攻略】 常驻池公开口径
    p4，单次获取 4★ 英雄的概率 约 10%【假设】 需实测校准
    r5，5★ 的重复率 随角色库变化，典型区间 0.5 至 0.95 由玩家状态决定
    Anchor，计量锚点 1 抽 = 5 枚书签 = 40 EM 本模块定义
    V0，单个新角色的价值 80 抽 = 3200 EM 由 1 / p5 推导
    G5，重复 5★ 发放量 180 EM【假设】 见 5.2 反推
    rho，实际回收率 rho = G5 / V0 = 0.056 计算得出

    5.2 预算红线反推发放量

    约束 C5 要求额外资源投放占月总产出的比例不超过 5%。设玩家月抽取 T 抽，则：

    月发放 EM = T × p5 × r5 × G5 + T × p4 × r4 × G4
月总产出（抽等价） = T 抽 = 40 × T EM
额外占比 = 月发放 EM / (40 × T) = p5 × r5 × G5 / 40

    取 r5 = 0.9，忽略 4★ 部分：

    G5 取值 对应 rho 额外占比（r5 = 0.9） 是否满足 C5
    120 EM 0.038 3.4% 满足
    180 EM 0.056 5.1% 临界，采纳
    240 EM 0.075 6.8% 不满足
    320 EM 0.100 9.0% 不满足
    480 EM 0.150 13.5% 严重超标

    这条表给出一个不算愉快但必须接受的结论：在 5% 的通胀红线内，能够提供的回收率上限大约是 0.06。想要把 rho 提到 0.15，额外投放会达到 13.5%，等于凭空增加一个中型活动的产出规模。

    5.3 rho 的敏感度与收益边界

    拥有率 r rho = 0.05（现状） rho = 0.056（本方案） rho = 0.10（越红线）
    0.50 0.525 V0 0.528 V0 0.550 V0
    0.70 0.340 V0 0.344 V0 0.370 V0
    0.90 0.150 V0 0.155 V0 0.180 V0
    0.95 0.100 V0 0.106 V0 0.140 V0

    可以清楚看到，价值路径的直接收益非常有限，在 r = 0.95 时只把 V(n) 从 0.100 V0 抬到 0.106 V0，提升约 6%。

    因此本方案的收益结构必须重新表述。真正起作用的是以下三条，按重要性排序：

    收益来源 作用机理 是否计入 rho 可量化方式
    确定性补偿 重复产出从"没有价值"变成"有进度条的价值" 否 以 EM 余额与兑换完成率衡量
    清单开放 提供商店原本不出售的兑换物 否 以清单各项的兑换占比衡量
    价值抬升 直接提高 V(n) 是 以 rho 计算

    如果评审只看 rho，会得出"收益太小不值得做"的结论。这个判断忽略了前两项，也正是本模块与简单的"多发代币"之间的区别。

    5.4 对既有 faucet 与 sink 的影响自查

    影响项 方向 幅度 判断
    天空石 faucet 不变 0 不触碰付费货币
    金币 faucet 不变 0 兑换清单不含金币
    体力 faucet 不变 0 兑换清单不含体力
    书签 faucet 增加 最多 5 抽等价 / 月 受 C5 约束
    终局材料 faucet 增加 由玩家在清单内自选 带月限
    典藏类 faucet 增加 不进入数值经济 不计入 C5，无月限
    新增 sink 新增 EM 兑换 等于新增 faucet 闭环，不产生沉淀

    需要注意的是，兑换上限必须按玩家而非按服务器统计，否则重度玩家的集中兑换会拉高整体投放。

    5.5 分人群预算校验

    2.5 已给出三类人群的 EM 收支。这里补充校验两条容易出问题的边界。

    校验项 肝帝 氪佬 又氪又肝 结论
    名义投放占比 4.1% 6.0% 6.3% 后两组超标，需靠上限约束
    实际投放占比（受 200 EM 上限后） 4.1% 1.3% 0.8% 全部守住 C5
    溢出 EM 规模 约 0 约 754 EM 约 1310 EM 必须由典藏类承接
    相对进度影响 不变 不变 不变 兑换物不含独占数值

    这里存在一个反直觉的现象：氪佬的名义获取量是肝帝的约 4.9 倍，但受上限约束后，两者实际能兑换的资源量接近。这看似削弱了付费回报，实际上是有意为之。因为本模块的资源类兑换受预算硬顶，付费玩家真正的额外回报不在资源类，而在典藏类与抽取次数本身。若资源类不限量，肝帝与氪佬的差距会被本模块进一步放大，那才是真正的风险。

    5.6 参数的版本校准方法

    当卡池概率或产出结构随版本变动时，按以下顺序重新校准，不可只调整单个参数：

    步骤 动作 依据
    1 重新测定 p5 与 p4 实机或官方公告
    2 重算 V0 = 1 / p5 × 40 EM 公式
    3 在 C5 红线内取最大可行 G5 5.2 的表
    4 用实际 r5 分布复核月投放 运营侧数据
    5 必要时下调清单折率而非下调 G5 避免影响 V(n) 的抬升

    7.2 发放逻辑伪代码

    function onSummonResult(player, result):
    if not result.isDuplicate:
        return
    amount = GRANT_TABLE[result.category]
    if amount <= 0:
        return
    key = requestId(player, result)          # 幂等键
    if Ledger.exists(key):
        return
    gained = min(amount, CAP_BALANCE - player.em.balance)
    Ledger.write(key, gained)                # 发放统一入口，entries不可改
    player.em.balance += gained
    pushClientDelta(gained)

    三条硬性约定：幂等键必须唯一且长期留存；余额截断与额度校验必须在扣减之前完成；所有变更只经 Ledger 这一个出口写入。

    7.3 兑换逻辑伪代码

    function redeem(player, itemId):
    item = getCatalogItem(itemId)
    if item is None:                          return ERR_NOT_IN_CATALOG
    if player.em.balance < item.cost:         return ERR_BALANCE
    usedMonth = player.em.usedThisMonth
    if usedMonth + item.cost > CAP_MONTH:     return ERR_MONTH_CAP
    if player.em.monthCount[itemId] >= item.monthLimit:
                                              return ERR_ITEM_LIMIT
    key = requestId(player, itemId)
    if RedeemLedger.exists(key):              return ERR_DUPLICATE
    grantItems(player, itemId)                # 发放走统一入口
    player.em.balance -= item.cost
    player.em.usedThisMonth += item.cost
    RedeemLedger.write(key, item.cost)
    return OK

    十．核心观点归纳

    10.1 四句话版本

    1. 方案要解决的不是出货率，而是"抽到的东西对我已经没用"这个导致长线付费塌方的结构性问题。
    2. 重复角色其实已有传承石与记忆烙印作为出口，所以本模块不是在重复造轮子，而是补上"回收来的东西对不上当期需求"这一半。受通胀红线约束，回收率只能做到约 0.06，对 V(n) 的直接抬升仅 6% 左右。

    3. 因此真正的价值来自另外两处：把无价值的重复变成有进度条的兑换资产，以及开放一批商店原本不出售的兑换物。收益主要体现在确定性与目标感，而不是数值。

    4. 三类人群都要照顾到：肝帝、氪佬与又氪又肝的 EM 获取量相差约 8 倍，资源类兑换用统一上限压住差距，多出来的部分导向不计入通胀预算的典藏类，因此既守住了经济，也没有把任何一类人关在门外。

    10.2 常见追问应答要点

    追问 应答要点
    传承石已经是回收机制了，为什么还要做 传承石出口固定且不随版本目标变化，回收来的价值对不上当期需求，且是一次性动作没有进度牵引。本模块补的是可对齐当期目标与可累积的那一半，不替换传承体系
    肝帝会不会因此追上氪佬 不会。资源类兑换有统一月度上限，两组实际可兑换量接近；差异体现在典藏类，而典藏类不含数值
    为什么不直接提高出货率 概率是不可回滚的改动，且对角色库完备玩家无效
    rho 只有 0.06，值不值得做 价值路径只是三分之一，另外两项不计入 rho
    会不会冲击既有商店 清单与秘密商店货物无重叠，且不触碰金币
    会不会诱导玩家多抽 设有边际监测，守护指标包含月均抽数上升 ≤ 10%
    如果效果不达预期怎么办 优先调整清单折率，不优先上调 G5
